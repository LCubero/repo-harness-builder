## Future observable outcomes

### Exact startup priority

For a relevant session-start, the future contract must consume evidence in this exact order:

1. the canonical harness soul/project charter;
2. verified conversation language and active stable preferences or continuing constraints from their existing declared owners;
3. the newest valid native backup's `Where We Left Off`; and
4. details only when objective relevance, contradiction, invalid or missing priority evidence, or mandatory repository reconciliation requires them.

The canonical project evidence remains authoritative throughout. Invalid, missing, stale, or contradictory priority evidence is reported and reconciled against its current repository owner; it is never silently inferred or made authoritative by the order above.

When Engram is callable, the relevant explicitly scoped recovery is availability evidence itself. The future contract must not add a separate probe or preflight, or repeat unchanged successful capability detail. Recovery failures and task-relevant discrepancies remain visible under the existing owner.

### Resume-first native continuity

Native continuity remains one exclusive, UTC-timestamped backup file per deliberate pause or close. Its future first resume section is `Where We Left Off`, containing exactly, in order:

1. `Next Action`
2. `Pending Work`
3. `Current Blocker`

Each empty value is `None.` Applicable claims retain the existing inline evidence labels: `verified fact`, `supported inference`, `unknown or unverifiable`, or `human decision required`; this scope adds no label taxonomy or inference rule.

Session-start must safely validate and select the newest eligible backup, read that resume-first content before later detail, and expand only for objective relevance, contradiction, invalid or missing priority evidence, or mandatory repository reconciliation. Repository evidence remains authoritative.

Session-stop must write the priority and resume-first content before detailed evidence. Detailed continuity remains afterward and does not become a second lifecycle, approval, receipt, or conflict owner.

### Generated-skill boundary

This scope establishes semantic read/write order only. `RH-W-0078` alone decides whether and how generated session skills split bodies or disclose dependencies progressively. The records do not merge.
