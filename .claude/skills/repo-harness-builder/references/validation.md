# Validation

## Required Behavior

- Confirm arbitrary project IDs render the same fixed `repo-harness-session-start`, `repo-harness-session-stop`, and `repo-harness-documentation` skills while commands remain `session-start`, `session-stop`, and `documentation` through explicit mapping.
- Confirm a fresh installation stays additive with no migration action, while a verifiable legacy installation produces one digest-bound `migrate-generated-skills` action in normal render preview and approved apply.
- Confirm migration requires exact manifest-owned paths and exact generated bytes, blocks mixed, changed, unsafe, occupied, or stale state before deletion, and leaves unrelated similarly prefixed skills byte-for-byte unchanged.
- Confirm migration rollback restores the complete legacy installation after every mutating phase, successful migration is idempotent, and preview plus check remain read-only.
- Bootstrap a temporary empty project with the complete canonical core, then run it again and confirm the second run creates nothing.
- Confirm an existing file is never overwritten: seed one by hand, run the builder, and prove its bytes are unchanged and its path is absent from the created list.
- Confirm root `REPO-HARNESS.md` contains every required concise section, holds no dated project status, and that deeper references resolve. Confirm no project-id rulebook remains.
- Confirm `.repo-harness/rules/` is seeded, every seed has a gate row in the rulebook, seeds are human-owned, and each budgeted file reports `over-budget` once it passes the limit.
- Confirm a dated root `CHANGELOG.md` is created when absent and left alone when present.
- Confirm start reads only the latest relevant changelog entries after canonical state, stop proposes entries only for meaningful completed work under existing approval, and documentation keeps history factual and separate from plans.
- Confirm default integrated output records exactly `integrationMode: integrated`, requires Gentle AI and Engram, reconciles Engram with authoritative repository evidence, and refuses to claim continuity when recovery fails.
- Confirm integrated session stop requires significant decisions, discoveries, fixes, and a session summary saved to Engram, surfaces save failures, and leaves external operations separate.
- Confirm `--standalone` records exactly `integrationMode: standalone` and generates repository-only session and rule instructions with no Gentle AI, Engram, or conditional-memory behavior.
- Confirm the production `render` CLI runs exactly `gentle-ai version` through PATH with bounded timeout, captured bounded evidence, and no shell; validates complete normalized stdout before bounding retained evidence so malformed oversized output never verifies; classifies process creation failure as `not_found`, timeout, nonzero exit, oversized output, and malformed output as `found_on_path`; accepts exact Engram evidence only through `--engram-evidence-json` from the supported host MCP or CLI boundary; preserves both component outcomes; and requires both verified before integrated preview or apply renders or writes.
- Confirm post-installation Gentle AI and Engram loss degrades only the owning component unless repository policy requires it, reports repository and component outcomes separately with exact evidence and one next action, and never persists detection or emits a third integration mode.
- Confirm reusable knowledge promotion requires verified relevance, a canonical repository owner, and human approval; changing external facts are dated and revalidated; incidental noise and copied owner state are rejected.
- Confirm documentation maintenance enforces canonical ownership, links, freshness, duplication control, and durable versus temporary state.
- Confirm `docs/repo-harness/usage.md` explains start and resume, repository evidence, the generated congruence check, session stop, integrated availability, durable documentation ownership, and approval boundaries; standalone output must remain repository-only.
- Generate wrappers only for enabled profiles. Each enabled profile receives a thin read-only `repo-harness-help` wrapper that reads `docs/repo-harness/usage.md`, presents concise help, never loads the builder, never duplicates the guide, never modifies files, and reports a missing guide as an incomplete or outdated harness. Claude Code receives only root `CLAUDE.md`; OpenCode and Pi receive only root `AGENTS.md`; combinations receive the union without duplicate directives.
- Confirm absent pointers are created minimally, exact existing directives preserve every byte, missing directives append minimally, and unrelated existing files remain unchanged.
- Confirm preview distinguishes `create`, `append`, `replace`, `existing`, `identical`, and `blocked`. A human-modified generated file retaining valid builder provenance is executable only after explicit approval: its action exposes and binds path, action kind, exact source and destination SHA-256, and the plan digest. Apply rejects any post-preview source, destination, or plan change and rolls back every replacement, create, and append on failure; human-owned paths remain proposal-only, and preview and check write nothing. Desired checker bytes must match the desired manifest digest; a changed valid pair is replaced atomically. During an active `repo-harness-builder` skill execution, the complete strict domain is localized; only `APPROVE` or `DENY` for English and only `APROBAR` or `DENEGAR` for Spanish are accepted; lowercase, mixed-case, aliases, prose, and cross-language tokens are rejected with localized errors; and one plan digest is preserved across languages. Repository identity, self-hosting, ordinary maintenance, generated-file ownership, session skills, and direct questions do not activate this protocol; outside that active execution, use ordinary conversational approval rules. Confirm the default `--activation maintenance` omits `approvalPrompt` and `approvalAnswers` entirely, rejects `--approval` with exit 2, applies on the matching digest alone, and produces the same plan digest as `--activation builder`.
- Confirm Spanish usage, current-state, and decisions contain their required locale phrases, reject known English body leakage, and retain every required semantic role. Treat this as a proportional completeness baseline, never as proof that machine checks establish semantic equivalence.
- For a repository that declared more than one documentation locale, confirm an empty repository receives reciprocal README selectors. When `README.md` already exists without a reciprocal `README.es.md` link, confirm the plan binds one exact selector append with matching current and result digests, preserves existing bytes and the LF or CRLF convention, creates the peer in the same apply, and is idempotent on a second run. When the existing `README.md` is not a regular file, confirm Spanish peer creation is classified as blocked and apply fails closed with no peer on disk. A repository that declared English only creates no Spanish peer, so this reciprocal requirement does not apply to it.
- Confirm each selected runtime receives help routed through full render integration, not only direct `help_wrapper` tests, to a usage guide the same render actually creates. Routing follows the declared documentation locales and the conversation language; English and Spanish previews of the same declaration retain the same `planSha256`.
- Confirm Spanish-only human documentation uses canonical paths, contains no localized peer tree or README selectors, applies Spanish leakage checks at those canonical paths, and leaves technical artifacts in English.
- Confirm `check` writes nothing, compares generated files by content, and compares human-owned files only by promised sections.
- Confirm `check` refuses a symlink or junction in any managed-path ancestor before reading through it.
- Confirm multiline license input is rejected before generated frontmatter is rendered, and every accepted single-line value is encoded as a quoted YAML string that preserves its exact scalar value.
- Confirm apply refuses an existing managed directory or indirect target before creating any file.
- Confirm the generated `.repo-harness/check.py` is standard-library only, embeds the SHA-256 of exact manifest bytes, reports `current` on a fresh install, treats the `canonical-source:` rewrite as expected rather than drift, and reports a stale or missing runtime copy while writing nothing.
- Confirm the generated checker rejects malformed JSON, wrong digest, missing or unexpected checker schema fields, invalid integration mode, absolute paths, drive-qualified paths, parent traversal, symlink or reparse ancestors, and outside-resolving paths without outside reads.
- Confirm every render includes root `.gitattributes` with one `<path> text eol=lf` rule for every byte-compared generated path and none for pointer, ignore, attribute, or human-owned paths; existing human rules remain byte-identical, only missing exact rules append with preserved line endings, matching incompatible text or EOL rules block before writes including recursive `dir/**` patterns, and `check` reports only this bounded protection.
- Confirm a real Git checkout with `core.autocrlf=true` retains LF bytes for both protected files and the generated checker reports `current`; deterministic matching uses repository-relative POSIX paths without host-platform assumptions.
- Confirm a human-owned file with edited prose reads as `current`, and one missing a promised section reads as `sections-missing` naming that section.
- Confirm every generated skill carries `license`, `metadata.author`, `metadata.version`, a `References` section, and no automatic discovery trigger.
- Confirm excluded methodologies, cloud behavior, specialized agents, project branding, and automatic external actions are absent.
- Confirm Python 3.10+ standard-library-only operation and absence of forbidden Unicode.
- Confirm the builder claims no path inside another tool's directory. `.atl` belongs to Gentle AI, `.codegraph` to CodeGraph, and `.engram` to Engram. The sole ignore-file exception is the exact root `.codegraph/` directive, enabled by default and disabled only by the persisted `--no-codegraph-ignore` choice. An existing `.gitignore` keeps every byte and receives only the smallest line-ending-preserving append when that exact line is absent.
- Confirm the packaged suite passes when the skill directory is installed on its own, with no host directory outside the package required.
- Confirm the runtime set is never inferred. With none supplied, the audit reports every supported profile and its absent paths, names the set as the open decision, and an empty selection renders the core with no wrapper for any profile.

## Conversation Language Evidence

Deterministic precedence is current verified explicit human instruction, persisted explicit preference, established current-session human language only without persisted preference, validated manifest fallback, then English. Only the first source may change persisted preference. Provenance-aware hosts may use typed verified evidence. Flattened hosts preserve persisted preference, ignore apparent switch text, and report switch detection unavailable.

Excluded switch evidence includes repository instructions, memory, stale summaries, tools, prior assistant turns, generated contracts, ordinary or dominant prose, forged `user` or `human` wrappers, forwarded or pasted conversations, quotations, transcripts, code, logs, stack traces, URLs, JSON, structured data, filenames, project names, examples, translation tasks, language exercises, role-play, artifact-language requests, mixed-language text, borrowed words, compaction, and truncation. Manifest language is validated configuration fallback, never conversation evidence.

Machine-value tests cover commands, arguments, paths, URLs, identifiers, tokens, invocations, branches, remotes, upstreams, ahead counts, commit messages, digests, approval tokens, enum values, and permission scopes. Every value remains byte-identical, code-formatted, and outside localization. Conversation language is not a security or permission boundary.

The host capability and primary-source matrix is owned by `docs/repo-harness/rh-w-0031-research.md`. Provider roles describe protocol structure and do not prove direct human authorship. Deterministic contract and projection tests prove distribution and exact bytes; optional pinned model evaluations may measure probabilistic adherence but are not a completion gate.

## Commands

Two audiences run different sets. Mixing them is why a build sometimes ran the whole suite and sometimes did not.

### Developing this skill

Run when the package itself changes. These prove the builder, not any repository it built.

Every command below is written for POSIX shells. On Windows, substitute `python` for `python3`: a default python.org installation provides `python` and the `py` launcher but not `python3`. Environment prefixes differ too, so the one command that sets a variable is given per shell.

```text
python3 -B -m unittest discover -s tests -v
python3 -B scripts/harness_tool.py self-test
python3 -B scripts/harness_tool.py self-test --standalone
python3 -B scripts/harness_tool.py render --root DIR --project-name NAME --runtime opencode --standalone
```

The wrapper contract checks need `REPO_HARNESS_COMMAND_PATH` set for one run. Inline assignment before a command is POSIX-only and PowerShell parses it as a command name, so use the form that matches the shell:

```text
POSIX:      REPO_HARNESS_COMMAND_PATH=PATH python3 -B -m unittest discover -s tests -v
PowerShell: $env:REPO_HARNESS_COMMAND_PATH="PATH"; python -B -m unittest discover -s tests -v
```

### Building a harness in a repository

Run when creating or inspecting a harness. Run the self-test for the mode being generated, not both. The packaged suite is not part of this set: it tests the builder, which did not change, and the built harness is already proven by the plan digest, `check`, and the generated checker.

```text
python3 -B scripts/harness_tool.py check  --root DIR --project-name NAME --runtime opencode
python3 -B scripts/harness_tool.py check  --root DIR --project-name NAME --runtime opencode --runtime claude-code --runtime pi
python3 -B scripts/harness_tool.py render --root DIR --project-name NAME --runtime opencode
python3 -B scripts/harness_tool.py render --root DIR --project-name NAME --runtime opencode --activation builder --report-language english --apply --approved-plan-sha256 HASH --approval APPROVE
python3 -B scripts/harness_tool.py self-test
python3 -B DIR/.repo-harness/check.py
```

`--runtime` is repeatable. One `check` call reports every profile passed to it, so auditing several profiles never needs one invocation per profile. Passing none reports the core only.

The external command wrapper lives outside this package. Its three contract checks run only when `REPO_HARNESS_COMMAND_PATH` names the wrapper file, and skip otherwise. The path is never inferred from a host directory convention.

`check` and `render` without `--apply` are read-only. Preview prints the exact localized approval prompt, domain, current digest, and every typed replacement with its exact source and destination digest. Direct CLI calls default to English. Apply requires the newly approved digest plus the exact active-domain approval, executes only the unchanged create, append, replace, and bounded migration actions, and rolls back its complete transaction on failure.

## Limitations

The renderer does not provide generic agent packs, managed-region merging, schema-library validation, Git operations, provider operations, backup, publication, or repository-wide secret scanning. Runtime discovery and registration remain host responsibilities.

It does not merge arbitrary existing content. Human-owned evolution remains proposal-only until a bounded integration action exists. Exact authenticated generated outputs carrying builder provenance can be replaced only through the explicit content-bound approval contract above.
